# Model provisioning is one decision, owned by ModelProvisioner

"Does a forecast exist for this ticker — and if not, what do we train?" used to be answered three different ways across the HTTP layer: a stale LSTM-era `.pt` file check, a string-match on exception text, and a `check_model_exists()` that ignored its arguments. We decided "provisioned" means one thing — the per-ticker scaler exists at `outputs/{ticker}/{ticker}_child_scaler.pkl` (parent: `outputs/parent/{parent_ticker}_parent_scaler.pkl`) — and the whole parent-then-child decision lives behind one module, `src/model/provisioning.py`, whose I/O (task registry, task starter, training functions, cache priming) is injected so tests cross the same seam as the HTTP layer.

The scaler-path rule, the canonical task ids (`parent_training`, `train_child_{TICKER}`), and the parent-before-child dependency all live in that module. Training a child when its parent is missing enqueues the parent and chains the child to start when the parent completes, so a client polls `/status` once instead of retrying. The `.pt` and `model.safetensors` existence tests are deliberately dead — the foundation model is a vendored constant, not something training produces.
